# Todo/calendar completion over local HTTP

A small Python teaching example: import assignments, mark the right linked todos
complete, read them back, and render the resulting calendar/manual-todo digest.
An agent only needs HTTP/JSON or a shell. No agent framework or LLM account is
required.

The repo includes three distinct kinds of evidence:

* `examples/historical_trace.{json,md}` is a sanitized real completion turn,
  with failed verification attempts retained. Treat its commands as archival data.
* `reference/` contains sanitized real project source snapshots for comparison.
  These are later snapshots, not necessarily the code used in the historical turn.
  Do not execute the reference delivery scripts.
* `examples/demo_trace.json` is a new local HTTP execution with fictional inputs.
  It is generated by the portable demo, not a replay of the historical system.

## Quickstart

Use an installed Python 3.11+ and [uv](https://docs.astral.sh/uv/). Run from the
repository root. Installing dependencies contacts the package registry; all
example runtime HTTP traffic stays on loopback.

```sh
export UV_CACHE_DIR="$PWD/.uv-cache"
uv sync --python /usr/bin/python3
uv run python -m unittest discover -s tests -v
uv run python -m todo_example.demo
uv run python scripts/privacy_check.py
```

On systems with a different Python path, pass that interpreter to `uv sync`.
`uv.lock` records the resolved dependencies. The demo starts its own server on
an OS-selected port, uses a temporary directory inside this repo, and removes
the store afterward. It prints before/after digests and writes
`state/demo_trace.json`. Regenerate the bundled synthetic trace explicitly with:

```sh
uv run python -m todo_example.demo --trace examples/demo_trace.json
```

The demo makes real POST, GET, and PUT requests, syncs twice without duplicates,
completes two linked assignments, reads their exact IDs back, syncs once more,
and verifies dates, completion timestamps, and an unrelated manual todo. Source
dates are fixed; UUIDs and audit timestamps change each run.

## Try the API yourself

In one terminal:

```sh
uv run python -m todo_example.server --data-file state/practice-todos.json --port 8765
```

In another terminal at this repo:

```sh
uv run python -m todo_example.sync --courses examples/fictional_courses --dry-run
uv run python -m todo_example.sync --courses examples/fictional_courses
uv run python -m todo_example.client list --filter all --q 'DEMO101_FALL - Module 2'
```

Inspect the full title and `link` fields. Set `TODO_ID` to one exact ID returned
by that list, then update and independently read it back:

```sh
TODO_ID='COPY_ONE_EXACT_ID_FROM_THE_LIST'
uv run python -m todo_example.client update "$TODO_ID" --json '{"completed":true}'
uv run python -m todo_example.client get "$TODO_ID"
uv run python -m todo_example.digest --courses examples/fictional_courses --start 2026-09-25 --days 1
```

The placeholder is not a real ID. The automated demo performs this matching and
verification without copying IDs. The interactive API docs are available at
`http://127.0.0.1:8765/docs` while your server runs. Stop it with Ctrl-C.

## How the pieces fit

```text
normalized course JSON -> sync ----POST/PUT----> local FastAPI -> JSON store
                              <-------GET-----/
agent / CLI ------------------GET/PUT--------/
course JSON + todo GET -> deterministic digest -> stdout only
```

* [Technical overview](docs/TECHNICAL_OVERVIEW.md): how each script works and how data moves through the system.
* [Agent instructions](docs/AGENT_INSTRUCTIONS.md): how to match, update, and verify.
* [API and input contract](docs/API.md): endpoints, JSON examples, and tool dispatch.
* [JSON tool schemas](docs/tool_schemas.json): usable function definitions.
* [Reference differences](docs/REFERENCE_DIFFERENCES.md): intentional changes,
  historical evidence limits, and optional Google/Discord boundaries.

The implementation lives in `todo_example/`. `server.py` adapts the reference
backend, `sync.py` and `courses.py` adapt reconciliation, and `digest.py` adapts
the calendar/manual-todo merge. `client.py` uses only Python's standard library.
`demo.py` provides disposable HTTP execution; `tests/` exercises the boundaries.

## Limits and public reuse

This is a single-user teaching service with no authentication. It binds
`127.0.0.1`, and the included client accepts literal loopback HTTP URLs only.
Other local processes can still access it. Run one server process per store:
the in-process lock and atomic file replacement do not coordinate multiple
processes or make a multi-request sync transactional. A failed sync can leave
some completed upserts; rerunning converges using stable links. Back up any
practice data you care about. There is no deletion endpoint, automatic archive,
automatic archive restoration, scheduler, collector, or delivery integration.

Only the requested digest date window and undated todos are rendered. Output is
not truncated to a message-service limit. Imported course dates require stable
IDs and explicit offsets for datetimes. See the input contract for matching and
date policies. Existing reference-format stores are not automatically migrated.

Keep `.venv/`, `.uv-cache/`, `state/`, `data/`, environment files, and any future
real data out of public archives. The privacy script checks included text for
some common secret formats and verifies immutable evidence hashes; it cannot
certify that arbitrary future content is private-data-free. Review before public
reuse.
